# FEAT-133 — Automated test record

**Item:** [FEAT-133](../items/FEAT-133-recipes-git-steps-in-blocks-run-with-an-agent.md)

## Rust

`crates/spagitty-core/src/recipes/`. The run, the restore point and the repository reader are tested against repositories built with `git`.

| Where | Cases |
| --- | --- |
| `mod.rs` | **The catalogue**: the spec's eighteen blocks in six groups, each with a key of its own and an example. **Closed**: no block's command has `--force`, `-D`, `--hard` or `clean` in it; a `forcePush`, a `reset` and a `shell` block are not steps; a parameter a block does not have is not read. A recipe is written in the spec's JSON form and read back, and one from before the switch has it off. Steps are described as the brief lists them. A pop takes the newest stash no pop before it took. The branch a step runs on follows the switches above it. **The screen's list is this one**: a test reads `src/lib/recipes/catalogue.ts`. |
| `command.rs` | **Each block is the command the catalogue says**, parameter by parameter. No block runs a force, a hard reset, a clean, a capital `-D` or `--no-verify`, with any setting. Fetching prunes when the setting says. A message the agent writes is marked until it has been written, and a typed one is never replaced. A name with a shell's characters in it is one argument. |
| `validate.rs`, **every rule, with a stack that breaks it and one that does not** | The spec's own recipe has nothing wrong with it. **Errors**: a pop with no stash above; a push after an amend, a reword, a squash or a rebase of commits the remote has, and not of commits it lacks, and not on a branch with no upstream; a branch deleted while checked out or while a later step uses it; a branch that does not exist and that no step above makes; more than 30 steps, a message over 72 characters, a note over 140; a message that is empty or more than one line; a message left to the agent with its help off, with no agent, or with one that cannot be used; a push to a never-unattended branch at *Full access* only; a new branch's name git would refuse, or one taken; a remote the repository does not have; a merge or a rebase of the branch onto itself; a cherry-pick of nothing, or of an option; a squash of fewer than two commits; a check that is not one of the repository's own; a recipe with no name, no step, or made for another branch; anything at all over an operation in progress. **Warnings**: a stash nothing pops; a pull, merge, rebase or switch over changes nothing above put away; a squash merge with no commit after it; a level above the repository's highest. With the help off the note and the agent are not read. Findings are in the order of the steps. |
| `brief.rs` | The guide carries its own version, and says the agent runs nothing and signs nothing. **The generated section is the spec's form**, compared whole. The brief is the guide and then the recipe. No note, no note section. Allowed commands are listed once, without names or messages. |
| `propose.rs` | The agent is shown every block and only what the repository has. Steps in a fenced block are read with what was said before them, and with no fence too. **A block that is not in the catalogue refuses the whole answer**, as does a parameter of the wrong shape, more steps than a recipe holds, and an answer with no steps. An empty array is an answer. A sentence is something short. |
| `script.rs` | The script is the steps, each under its comment, compared whole. The guards are what a shell can do. A message left to the agent is left to the editor. What is not plainly one word is quoted. |
| `restore.rs`, **restore and undo on a scratch repository** | Making one writes down what was and changes nothing, and its snapshot holds a file git did not know about. **Undoing puts back `HEAD`, the branches, the index, the tree with its untracked file, and the stash list**, after a stash with untracked files, a new branch, a commit, a merge, a moved branch and a dropped stash; the branch the run made is gone. It ends a merge that stopped on a conflict, goes back to a detached `HEAD`, and never deletes a file git did not know about. No commit yet, and conflicts in the index, refuse one. Listed newest first and dropped one at a time. **The newest twenty are kept and none older than seven days.** |
| `run.rs`, with a host that records | **A run leaves what the same commands typed by hand leave.** It begins with a restore point and nothing else. **Each level's stops**: *Ask every step* before each step; *Ask before pushing* before a push and a branch being deleted; *Full access* runs through; *Read-only* runs nothing; a level above the repository's highest runs at the highest. *Stop and ask me* stops at *Full access* too. A stack that cannot run is refused with what is wrong. **A conflict**: a merge stops with its paths and its ways on; it is gone on from once nothing is conflicted, and not before; aborting ends the merge and the run and keeps the steps before; taken to Merger, it is aborted here and gone on from once it is merged; a rebase is continued or aborted; a pop cannot be aborted and drops its stash once resolved. **A failure**: stops, and is run again, skipped or ended; running again starts from the command that failed. *Stop unless clean*. A check that fails. A push the remote rejects. **The agent**: with the help on it writes a message from the changes, one line and no trailer; a message it gets wrong stops the run before anything is changed; it is asked what went wrong. **With the help off no agent is asked for anything.** A repository that changed while the run waited is looked at first. *Stop* ends the run before the next step. *Undo the whole run* leaves the repository as it was, from the end and from a conflict. A run is its own record. |
| `world.rs` | It reads the branches, what is checked out and whether there are changes; a detached `HEAD`; a stopped merge; the commits the upstream lacks; and which rebases would replay commits the upstream has. |
| `src-tauri/src/recipes.rs`, the pure parts | Recipes are kept in a file of their own and read back; a file that cannot be read is an error and not an empty list. A recipe is saved in its own place and a name is one recipe's. Import refuses what is not a recipe, a block that is not in the catalogue, and a newer version. The never-unattended branches include the ones a recipe makes. The levels are 2.0's four. A run's record is kept, the newest is read back, and only twenty are kept. |
| The same file, **through the commands**, on a mock application with a real repository open | A recipe is saved, listed and checked against the open repository. With the help on, the brief is the guide and then the recipe. **A run runs on a thread of its own and tells the screen**: the events, the lines, the record and the restore point. It waits for the person and goes on when answered; a second recipe is refused meanwhile. A choice that cannot be taken leaves it waiting. *Stop* ends a run that is waiting. **Undoing the whole run puts the repository back**, untracked file and all. A restore point is gone back to and dropped. A stack that cannot run does not start, and with the help off nobody proposes anything. |

## Not covered

- **The application.** Nothing was run in the built application: no recipe was run from the screen against a repository.
- **An agent.** `agents::ask` is the one new function with no test: no command-line agent was started and no model was called. What an agent answers is tested as text, in `propose.rs` and `run.rs`.
- **A remote that needs credentials.** Pushes were to a bare repository on disk.
- **A check.** *Run checks* is tested with a host that answers; the farm's runner it calls in the application has its own tests and was not run from a recipe.
- **A recipe run while the person uses the toolbar.** The lanes are tested as the store holds them. Two gits at once were not tried.
- **macOS and Linux.** The Rust tests were run on Windows only.
